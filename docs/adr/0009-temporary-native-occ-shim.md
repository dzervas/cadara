# Use a temporary native OCC bridge while targeting BRepGraph

The custom OCC WASM build carries a temporary pre-8 native topology shim to batch kernel extraction/history work instead of making TypeScript drive repeated per-subshape JS/WASM calls. Waiting for OCCT 8 would avoid throwaway code but leave that boundary-crossing cost in place; exposing more OCC classes to JavaScript would retain the expensive calling pattern. The intended replacement is OCCT 8/BRepGraph-owned topology identity and history: the bridge is not a permanent compatibility layer and is to be deleted once that migration owns its responsibilities.

The deletion boundary is explicit in the [native topology helpers](../../occ-native-shims/cadara-native-topology-helpers.inc); the [custom build recipe](../../opencascade-recipe.yaml) and [filesystem runtime loader](../../src/infrastructure/occ/filesystem-kernel-runtime.ts) embody the shipped build choice. This records the bridge and its retirement condition, not a claim that the BRepGraph migration has happened. Historical rationale: `cadara-dd3.177`, original design decisions “Target OCCT 8/BRepGraph as the real topology model”, “Add a temporary pre-8.0 native shim, then delete it” and “Native commands return flat kernel payloads”.
