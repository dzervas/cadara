# Persist authored documents through Automerge, not kernel snapshots

Use `automerge-repo` behind `DocumentRepository` as the durable authored-state store, not as a React state model or a container for the old replay log. Authored CAD records are the collaboration input; derived render meshes, diagnostics and presentation snapshots are regenerated because persisting them would enlarge the CRDT and let derived data become stale. Accept the rebuild cost and keep Automerge handles behind the repository rather than replacing the modeling facade with Automerge React hooks; `automerge-repo` owns storage chunks and compaction instead of a hand-rolled incremental IndexedDB store.

The boundary is embodied by [`AuthoredModelDocument`](../../src/contracts/modeling/authored-document.ts) and the [IndexedDB Automerge repository](../../src/infrastructure/persistence/indexeddb-automerge-document-repository.ts). See [ADR 0001](0001-layered-runtime-boundaries.md) for layer placement. Historical rationale: `cadara-dd3.49`, original design “Decisions” (repository boundary, authored state versus snapshots, automerge-repo, and operation history) and “Risks / Trade-offs” (rebuild cost).
