# Keep one semantic modelling API beneath programmatic adapters

The typed TypeScript SDK and CLI recipes use the same semantic session and target resolver rather than owning separate modeling semantics or history stores. SDK operation types come from the closed semantic command union, not a hand-maintained fluent API per feature family, so adding a second caller surface does not create a second contract that can drift. Handles hide basis/draft bookkeeping from script authors while preserving the semantic session's conflict and outcome rules; the trade-off is that the ergonomic API remains bounded by that shared command model.

See the [semantic session ports](../../src/application/semantic/ports.ts), [SDK](../../src/application/semantic/sdk.ts), [generated operation types](../../src/application/semantic/sdk-types.ts) and [CLI recipe runner](../../src/cli/commands/document-recipes.ts). The [agent-interface research](../research/agent-modelling-interface.md) records why the semantic layer was retained while the one-shot JSON interface was insufficient in sections 11a and 12. Historical rationale: `cadara-kkl.15`, “What to build” (single seam, generated operations and handle chaining). Validation-lane policy remains in the [testing guide](../testing.md).
