# Use authored JSON for native open/save and file-menu export

Native open/save, autosync and file-menu export use one serialized authored-document JSON object, not a ZIP package containing `document.json` and binary members. ZIP packaging had given the native extension two competing meanings; the deliberate breaking reversal chose an inspectable authored-data contract over compact packaging, and rejected a dual ZIP/JSON compatibility reader because it would preserve that ambiguity. Historical rationale: `cadara-dd3.130`, original design decision “`.cadara` is single JSON, not a ZIP container” and “Risks / Trade-offs”.

These paths use the [authored-document serializer](../../src/contracts/modeling/authored-document-serialization.ts), [local filesystem adapter](../../src/lib/local-file-system-access.ts) and `exportCurrentDocumentNow` in the [modeling service](../../src/domain/modeling/modeling-service/service.ts). A remaining exception is `ModelingService.exportDocument({ format: "cadara" })`: it serializes `snapshot.document` as `KernelDocumentSnapshot` through [`stringifyCadaraDocument`](../../src/domain/modeling/modeling-service/helpers.ts), as the [snapshot-export regression](../../src/domain/modeling/modeling-export.spec.ts) preserves. This ADR does not claim those export schemas are unified or prescribe the encoding/storage policy of every geometry asset.
